# 前端规格与任务清单

====================================================================
## 第一部分：全局约定（所有任务都遵守）
====================================================================

### A. 交互原则
- 能撤销的本地操作直接执行，不出预览卡；所有结果都生成新版本；删除的文件先进 .gvpak/trash
- 只有三种情况需要确认，确认方式是对话里一行文字加 [继续] [取消] 两个按钮，不弹窗：
  1. 看图描述单次超过 20 张
  2. 生图单次超过 4 张，或预估费用超过上限（默认 ¥2）
  3. 本账号配额即将用完（剩余不到 5%）
- 处理对象的确定顺序：@引用 > 当前选中 > 编辑器里打开的那张 > 当前筛选结果（超过 50 张时一行确认）
- 发给 DeepSeek 的只有原文件名，不带路径
- 不使用 alert / confirm / 模态弹窗来确认操作；只有 @ 素材选择器、斜杠命令列表、右键菜单可以用浮层
- 代码里没有「平台」这个概念；比例只有 1:1 / 3:2 / 4:3 / 4:5 / 16:9，加一个 ⇄ 横竖切换
- 导出时目标文件已存在，自动改名为 xxx (2).jpg
- 只做桌面端，最小宽度 1280px，只支持 Chrome 和 Edge；主题跟随系统深色/浅色

### B. 技术栈
- 如果项目里已经有前端框架：沿用现有框架、构建工具和目录结构，不迁移、不重写
- 只有从零开始时，才使用推荐组合：TypeScript + Vite + React 18 + Zustand + CSS 变量（不引入 UI 组件库）
- coverflow 模块：直接使用原版，内部代码不改；只通过它已有的接口（参数、事件、回调）接入数据
- 列表虚拟化：素材网格必须虚拟化（现有项目里有虚拟列表就沿用，否则用 @tanstack/react-virtual 或自己写）
- 缩略图生成放在 Web Worker 里，用 OffscreenCanvas + createImageBitmap
- 文件夹句柄存在 IndexedDB，持久授权使用 File System Access API 的 queryPermission / requestPermission
- 实时通信：任务进度、排队位置、素材更新都用 WebSocket；后端已有 SSE 的话就用 SSE，不用两套

## 第二部分：前端架构
====================================================================

### C. 路由
- /                首页
- /library         素材库（查询参数保存筛选条件：?folder=&tag=&status=&q=&sort=）
- /editor/:assetId 编辑器
- /settings        设置（只有主机本机能打开；同事端进入时跳回首页，接口返回 403）
- 刷新页面后筛选条件、当前项目、对话栏宽度和收起状态都能恢复（存在 localStorage）

### D. 目录结构（只在新建时使用；已有项目的话，把同样的职责对应到现有结构里）
    src/
      app/            路由、AppShell、全局快捷键
      stores/         session / project / assets / selection / tasks / chat / editor / prefs
      services/       api.ts（HTTP）、realtime.ts（WS）、fs.ts（文件夹授权与读写）、hash.ts（Worker 里算 SHA-256）
      workers/        thumb.worker.ts、hash.worker.ts
      features/
        home/         HomePage、QuickCommands、RecentList
        library/      LibraryPage、FolderTree、FilterBar、AssetGrid、AssetTile、BatchMenu、SmartGroups
        editor/       EditorPage、Canvas、ToolRail、RatioBar、VersionBar、PropsPanel、CoverflowHost
        chat/         ChatPanel、MessageList、ExecRow、ConfirmRow、AssetGridCard、ErrorCard、Composer、MentionPicker、SlashMenu
        tasks/        TaskIndicator、TaskDrawer
        settings/     SettingsPage（五组设置）
      ui/             Button、IconButton、Segmented、Badge、Tooltip、Resizer、Banner、Spinner、Kbd
      styles/         tokens.css、base.css
      lib/            shortcuts.ts（快捷键作用域）、slash.ts（斜杠命令解析）、target.ts（处理对象解析）、ratio.ts

### E. 状态模型（每个 store 职责单一，组件不直接调接口）
- session：账号、是否主机、是否本机访问、配额（已用/上限）
- project：当前项目、文件夹句柄、授权状态（granted / prompt / denied），最近项目
- assets：素材索引（id、文件名、相对路径、hash、尺寸、标签、描述状态、是否已抠图、版本数、处理状态）、筛选条件、排序、派生的筛选结果
- selection：selectedIds（有序）、lastAnchorId（给 Shift 连选用）、派生的 SelectionContext
- tasks：任务列表（id、类型、对象数、进度、状态、排队位置、所属账号、开始时间），WebSocket 推送后实时更新
- chat：对话列表、当前对话、消息、执行行状态机
- editor：当前 assetId、当前版本、当前工具、比例状态 {ratio, orientation}、属性参数、对比开关
- prefs：对话栏宽度、是否收起、文件夹树宽度、网格尺寸档位、列表/网格视图

### F. SelectionContext（发给后端和 DeepSeek 的唯一上下文）
    {
      page: "home" | "library" | "editor",
      mentions: string[],              // @ 引用的素材 id
      selected: string[],              // 当前选中
      editorAssetId: string | null,
      filter: { folder, tag, status, q, sort },
      filteredCount: number,
      resolvedTarget: { source: "mention" | "selected" | "editor" | "filter", ids: string[] },
      fileNames: string[]              // 只有文件名，没有路径
    }
- resolvedTarget 由 lib/target.ts 按全局约定的顺序计算，是纯函数，要有单元测试
- 选中状态变化后 100ms 内更新；变化频繁时用 rAF 合并，不用 setTimeout 防抖

### G. 执行行状态机（ExecRow）
    resolving → planning → [awaiting_confirm] → running → done | partial | failed | cancelled
- resolving：显示「对象：已选 12 张」（来源：@引用/选中/编辑器/筛选）
- planning：显示「方案：抠图 → 白底 → 4:5」，折叠成一行，可以展开看参数
- awaiting_confirm：只在门槛情况下进入，显示 ConfirmRow
- running：进度条显示 n/N，带 [停止 Esc]；对应缩略图实时显示转圈角标
- done：「✓ 完成 N 张」 [撤销] [导出] [在素材库中查看]
- partial：「完成 N 张 · 失败 M 张」 [重试失败项] [查看原因]
- failed / cancelled：一句人话说明原因，带 [重试]
- 斜杠命令跳过 planning，直接进入 running

### H. 快捷键作用域（lib/shortcuts.ts 统一管理，组件不各自监听 keydown）
- 优先级：输入框聚焦 > coverflow 模块聚焦 > 页面作用域 > 全局
- 输入框聚焦时：单键快捷键全部失效（1–5、R、Delete、Space、←、→），只保留 Esc、Ctrl+K、Ctrl+J
- coverflow 模块聚焦时：它原有的按键优先；1–5 和 R 如果和它冲突，就不在它聚焦时生效
- 全局：Ctrl+K 聚焦输入框，Ctrl+J 收起/展开对话栏，Ctrl+Z / Ctrl+Shift+Z 撤销/重做批量操作，Esc 停止当前任务或关闭浮层
- 素材库：Ctrl+A 全选当前筛选，Delete 移入回收站，Enter 打开编辑器
- 编辑器：1–5 选比例，R 切换横竖，按住 Space 看原图对比
- 实现时先读 coverflow 模块的按键表，写进 shortcuts.ts 的冲突表

## 第三部分：视觉规范（styles/tokens.css）
====================================================================

### I. 尺寸
- 顶栏高度 48px
- 对话栏宽度 360–520px，默认 400px，可拖动；收起后宽度为 0，右边缘留一个 24px 的展开把手
- 文件夹树宽度 180–320px，默认 220px，可拖动
- 编辑器左侧工具栏宽 48px；画布上方工具条高 40px；版本条高 40px
- coverflow 区域的高度和布局沿用原版
- 网格缩略图三档：120 / 160 / 200px，间距 8px，用 Ctrl+滚轮切换档位
- 间距按 4px 递增：4 / 8 / 12 / 16 / 24 / 32
- 圆角：控件 6px，卡片 8px
- 字号：12（辅助文字）/ 13（正文）/ 14（标题）/ 20（首页主标题），系统字体栈

### J. 颜色（用 CSS 变量，浅色和深色各一套，通过 prefers-color-scheme 切换）
- --bg、--bg-elev、--bg-sunken、--border、--text、--text-dim、--accent、--success、--warning、--danger、--focus
- 选中的素材：2px --accent 描边，加 --accent 10% 透明度的底色
- 授权失效提示条：--warning 背景，固定在顶栏下方，高 32px
- 透明背景的预览用棋盘格底纹（--checker-a、--checker-b）

### K. 状态与反馈
- 每个区域都要有四种状态：加载中（骨架屏）/ 空 / 错误（带重试）/ 正常
- 不用 toast 显示成功信息；结果统一显示在对话栏的执行行里
- 所有可点击的元素都有 hover、active 和 :focus-visible 样式（2px --focus 外描边）
- 图标按钮必须有 aria-label 和 Tooltip（显示快捷键）
- 动画时长不超过 150ms；系统开启 prefers-reduced-motion 时关闭动画

### N. 素材库

    │ 文件夹树   │ [搜索…] [标签 ▾] [状态 ▾] [排序 ▾]  ▦ ☰ │ 40px

- 素材卡片：缩略图（按比例完整显示，透明背景用棋盘格）、文件名（一行，超长省略）、角标

### O. 编辑器
    ┌────┬──────────────────────────────────┬──────────────┐
    │    │ [1:1][3:2][4:3][4:5][16:9][⇄] │ ⟲ ⟳ │ [对话][属性]  │ 40px 工具条
    │ ✂  ├──────────────────────────────────┤              │
    │ ⌖  │                                  │              │
    │ ⬚  │             画布                   │  对话栏或属性面板 │

    │ ⟲  │                                  │              │
    ├────┴──────────────────────────────────┤              │
    │ 版本条：原图 → 抠图 → 白底 → 4:5 ●         │ 40px         │

    └───────────────────────────────────────┴──────────────┘
- 左侧工具栏：抠图、居中、裁切、掩膜画笔（加/擦，用 [ ] 调画笔大小）、旋转纠偏
- 画布：滚轮缩放（以鼠标为中心），拖动平移，双击回到适应窗口；透明区域显示棋盘格
- 版本条：横向排列的节点，点一下切到那个版本（不删除后面的版本），当前版本有实心圆点，hover 显示步骤和参数
- 右侧栏分两个标签页：
  - 对话：同一个 ChatPanel，处理对象默认是当前这张
  - 属性：长边像素（留空 = 原图尺寸）、适配方式（自动 / 补边 / 裁切）、补边颜色、背景色

- coverflow 模块：直接使用原版，交互不改
  - 数据来源：有选中时显示选中的图；没有选中时显示当前筛选结果；批量任务完成后显示本批结果
  - 在 coverflow 里切换到某张图时，editor.assetId 和 URL 同步更新
  - 只增加一层处理状态角标（转圈 / 失败），设置 pointer-events: none

### P. RatioBar 组件（编辑器工具条、批量菜单、右键菜单共用一个组件）
- 6 个按钮：1:1 / 3:2 / 4:3 / 4:5 / 16:9 / ⇄，用 Segmented 样式，当前比例高亮
- 默认方向：3:2、4:3、16:9 是横向；4:5 是竖向；1:1 没有方向
- 点比例按钮：方向回到这个比例的默认方向，并立即对处理对象执行 fit_ratio
- 点 ⇄：对调当前比例的宽高（3:2↔2:3，4:3↔3:4，4:5↔5:4，16:9↔9:16），并立即执行；选 1:1 时 ⇄ 置灰
- 按钮上显示实际比例：切换方向后，按钮上的 16:9 显示为 9:16
- 不显示任何「平台」名称
- 每次点击生成一个新版本，用 Ctrl+Z 撤销
- 比例换算写在 lib/ratio.ts（纯函数，要有单元测试）

### Q. ChatPanel
- 顶部：对话切换 ▾、[+新对话]
- 消息流：自动滚到底部；用户往上翻看历史时不强制滚到底，显示一个「↓ 新消息」按钮
- 卡片只有五种：
  - Text：流式输出的 Markdown
  - ExecRow：见 G
  - AssetGridCard：最多显示 12 张，点「+N」把这些素材选中并跳到素材库
  - ConfirmRow：一行文字加 [继续] [取消]
  - ErrorCard：带 [重试] [跳过]
- Composer（输入框）：
  - 自动增高，最多 8 行
  - 输入框上方显示「已选 N 张 ✕」，文字是对象来源的说明，例如「已选 12 张」「当前图」「筛选结果 36 张」
  - @ 打开 MentionPicker：按文件名或标签搜索，↑↓ 选择，Enter 插入；插入后显示为一个标签（chip），按退格整体删除
  - / 打开 SlashMenu：/白底 /抠图 /居中 /比例 /导出 /撤销；/比例 后面接参数，例如「4:5」「16:9 竖」
  - Enter 发送，Shift+Enter 换行，Esc 停止当前任务
  - 输入框为空时按 ↑：编辑上一条消息，发送后先撤销上一条的结果，再重新执行
  - 拖入图片：导入项目，变成 @ 引用

### R. 顶栏与任务抽屉
- 项目 ▾：最近项目列表，以及「打开文件夹…」
- 任务指示：显示运行中和排队中的任务数，有任务时图标转圈；点击展开任务抽屉
- 任务抽屉：从顶栏向下展开，最大高度为窗口高度的 60%
  - 分组显示：运行中 / 排队中（显示「前面还有 N 个（主机优先）」）/ 最近完成
  - 每个任务可以 [停止]、[取消]、[查看结果]
- 配额：显示百分比，hover 显示已用/上限；超过 95% 时变成警告色
- 账号 ▾：主机在本机访问时，多一个「设置」入口

### S. 设置页（只有主机本机能打开）
- 左侧分组导航，右侧表单，分五组：
  1. API 密钥：只能写入，显示「已设置 ••••」，[替换]
  2. 模型选择
  3. 账号与配额
  4. 费用上限与确认门槛：20 张 / 4 张 / ¥2 / 50 张，四个值都可以改
  5. 证书：指纹（可以复制）/ [重新生成] / [下载 安装证书.cmd]
- 修改后自动保存，字段旁边显示「已保存」，不需要点保存按钮

### T. 性能指标
- 5000 张素材的网格滚动保持 60fps；首屏缩略图 1 秒内出现
- 选中状态变化后 100ms 内同步到 SelectionContext
- 斜杠命令从发送到进入 running 不超过 300ms
- 任务进度从推送到界面更新不超过 200ms
- 缩略图按 hash 缓存在 IndexedDB，第二次打开不重新生成

P4 内部顺序：4.0 → 4.1 → 4.2 → 4.3 → 4.4 → (4.5、4.6、4.7、4.8 可以同时做) → 4.9 → 4.10 → 4.11

## P0 基础与安全
- [ ] 0.1 证书脚本：生成自签名证书，显示指纹，生成「安装证书.cmd」
      验收：同事电脑运行脚本后，Chrome 和 Edge 打开没有安全警告；页面上显示的指纹和主机一致
- [ ] 0.2 API 密钥迁移到 DPAPI：读取旧明文 → 加密保存 → 删除明文
      验收：配置文件里搜不到明文密钥；任何接口都不返回密钥；设置页只能写入
- [ ] 0.3 账号、配额计数、本机访问判断
      验收：同事账号看不到设置入口；直接访问 /settings 的接口返回 403

## P1 文件与数据
- [ ] 1.1 文件夹模式：持久授权，建立 .gvpak/（versions/、trash/、cache/）
      验收：重启浏览器后不再弹授权；授权失效时只显示提示条，点一下就恢复
- [ ] 1.2 二进制上传，SHA-256 哈希去重（在 Worker 里计算）
      验收：同一张图第二次上传没有任何传输量
