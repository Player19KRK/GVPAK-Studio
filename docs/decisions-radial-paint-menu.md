## 已确认的默认规则

- 色卡采用三圈，每圈 24 个格位，共 72 格，其中一格为吸管。沿圆周组织色相，沿半径组织明暗，另安排中性色。色块本身实色，底盘半透明。
- 画笔二级保留选中入口，在其外侧使用大小、硬度、不透明度三条平行短弧；橡皮使用两条。参数状态去掉背景盘、外圈和中心按钮，点击保留的工具入口返回一级。显示简短英文名称和当前数值，沿用项目界面语言。
- 轨道视觉上细，但有更宽的透明命中区域。滚轮只调整鼠标悬停的参数，并阻止该事件触发画布缩放或页面滚动。键盘聚焦时允许方向键微调。
- 一级中心关闭；色卡中心返回一级；参数区点击工具入口返回。Esc 每次退一层；点击菜单外关闭并吞掉此次画布落笔。菜单开启时停止绘画及画布拖拽。
- 右键入口限定图片画布。菜单靠近边界时整体向内平移，保留方向排列，避免扇区被裁切。无图片时不显示绘画菜单。
- 吸管进入图片取色模式，取当前编辑结果的颜色，不采样菜单、背景或面板；成功后关闭取色并回到画笔，Esc 取消。图片取色不依赖系统级屏幕吸管。
- 空格按住临时平移，松开恢复绘画工具；显式区分绘画工具与现有调整面板状态。
- 笔迹作为独立绘画数据保留，橡皮不会擦坏原图。笔迹跟随图像裁剪、旋转和翻转；每一笔作为一个撤销步骤。调整笔刷设置不产生图片历史记录。
- 开关菜单、调整笔刷设置不改变现有笔迹；颜色调整面板作用于底图，绘画色保持所选颜色。
- 层级过渡短促，其他一级项淡出后不可交互；遵守系统减少动画设置。

## 技术方案比较

### 方案 A：Svelte + SVG 菜单，Canvas 2D 绘画预览，Rust 保存与导出（推荐）

- 技术栈：沿用现有 Svelte 5 和 Rust；使用浏览器原生 SVG 路径绘制扇区和弧形滑杆，Canvas 2D 展示绘画层；共享笔迹规则。
- 为什么适合：扇区、细分色卡与弧形轨道可精确表达；菜单状态、文字、键盘操作便于与现有界面衔接。
- 开发难度 / 维护成本：中等；主要工作量是绘画数据与预览、保存、导出的完整衔接。菜单无需新增第三方 UI 库。
- 目标地区能否顺利使用：继续本地运行，不新增在线服务或运行时 CDN。
- 需要自行管理：现有前后端源码及构建产物；无新增账号、密钥或服务器。
- 主要风险：浏览器绘画预览与 Rust 最终像素的一致性，以及缩放、裁剪、旋转后的坐标映射，需要实际验证。

### 方案 B：Canvas 2D 绘制菜单及绘画层，Rust 保存与导出

- 技术栈：Svelte 管理状态，菜单视觉与绘画使用 Canvas 2D，Rust 承接保存和导出。
- 为什么适合：可以统一控制菜单绘制和复杂动画。
- 开发难度 / 维护成本：较高；需额外维护扇区命中、文字排布、键盘语义及焦点对应关系。
- 目标地区能否顺利使用：同样本地运行，无新增在线依赖。
- 需要自行管理：现有前后端源码以及额外的菜单绘制、命中逻辑；无新增密钥或服务器。
- 主要风险：交互维护成本较高，对当前仅三项一级菜单没有明显收益。

推荐 A：SVG 直接对应本次扇形和圆弧几何，适合现有组件体系。B 不减少真实绘画与后端衔接的工作。
