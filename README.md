# GVPAK Studio

面向产品图片处理与小团队协作的图像工作台。支持本地图像编辑、AI 场景生成、自然语言处理流程和批量导出，提供中文界面及局域网团队访问。

![GVPAK Studio 功能概览](docs/presentation/GVPAK-Studio-Overview-Simple-16x9.png)

## 快速开始

1. 下载完整项目，在 Windows x64 电脑上解压。
2. 双击 `一键启动.cmd`（也可运行 `start.cmd`）。
3. 在浏览器打开 <http://127.0.0.1:8787/>。
4. 导入图片，开始编辑；使用 AI 功能前，在“设置”中配置自己的服务商和 API 密钥。

仓库包含 Windows 可执行程序和已构建的前端，直接运行无需安装 Node.js 或 Rust。降噪、自动居中和纠偏等工具需要可用的 Python/OpenCV 环境，可在“设置”中查看工具状态。AI 服务可能产生费用，按所配置服务商的规则计费。

## 主要功能

- **图像编辑**：调色、自由或比例裁剪、变换、前后对比、缩放和平移、RGB 直方图、版本保存与草稿恢复。
- **绘画工具**：右键打开径向菜单，选择颜色、画笔或橡皮；支持大小、硬度、不透明度、取色、撤销与重做，绘画结果可随图片保存和导出。
- **项目管理**：点击左上角品牌或项目名称进入项目视图，创建或重命名项目、浏览封面、批量选择图片，以及删除和恢复。
- **AI 生成**：使用文字描述生成图片，或加入参考图片生成产品场景；支持结果预览与采纳、模型选择和费用估算。
- **自然语言流程**：描述目标，例如“产品主图，800×800，100 KB”，检查计划后执行；本地步骤支持采样、比较、应用和可复用预设。
- **批量导出**：支持 WebP、JPEG、PNG，设置尺寸、裁剪或填充方式、质量和目标文件大小，并查看逐图进度与结果。
- **团队协作**：同事通过局域网 HTTPS 登录各自工作区，共用主机配置的 AI 服务，支持任务排队、下载和问题反馈。

## 使用提示

编辑草稿会在浏览器中暂存，点击“保存”或按 `Ctrl+S` 保存当前图片版本。导出和处理支持切换图片范围。

底部图片浏览区支持快速多选：鼠标位于展开的浏览区时，按空格切换当前图片的选择状态；按住空格并滚轮浏览，或按左右方向键，连续选择或取消选择经过的图片。一次按住期间保持同一种选择操作。

拖动画布与底部浏览区之间的分隔线可调整高度，拖动画布右侧分隔线可调整属性面板宽度；双击分隔线恢复默认尺寸。画布支持 GPU 交互预览，保存及导出使用 Rust 图像处理结果。

## 局域网团队使用

主机运行 `一键启动.cmd`，在“设置”的团队访问中为同事创建账号，再运行 `开启局域网访问.cmd`。同事按主机提供的证书与 HTTPS 地址登录。

各账号使用独立工作区。选择本机保存目录后，浏览器在写入和校验成功后通知主机清理对应图片副本；未保存的临时图片按 24 小时保留规则处理。主机个人项目不在此清理范围内。登录可选择在当前设备保持 30 天。

## 数据与密钥

本机默认数据目录为 `backend/studio-data/`，团队账号、证书和临时工作区位于 `backend/team-private/`。API 密钥通过应用设置写入 Windows 凭据管理器。

这些运行时数据、私有证书、密钥、日志和本地验证产物不包含在仓库中。使用者需要配置自己的服务凭据；团队 AI 请求使用主机配置的服务商。

## 本地开发

前端使用 Svelte 5 和 Vite，后端使用 Rust。需要 Node.js、npm 和支持 Rust 2024 edition 的工具链。

```powershell
npm ci
npm run dev
npm run check
npm run build
npm run test:p1
npm run test:p2
cargo test --manifest-path backend/Cargo.toml
cargo build --release --manifest-path backend/Cargo.toml
```

前端构建输出为 `dist/`。后端重新构建后，需要将生成的可执行程序复制到启动脚本使用的 `bin/gvpak-studio.exe`。

接口说明见 [命令契约](docs/command-contract.json)，绘画实现说明见 [径向绘画工具设计](docs/decisions-radial-paint-menu.md)。

## 功能范围

当前提供基础图像调整及绘画叠加，不具备 Photoshop 式多图层合成、PSD 编辑或修复画笔等完整专业修图功能。AI 生成功能依赖所配置服务商的模型和可用性。

## 命名升级与已有配置

可执行程序统一为 `bin/gvpak-studio.exe`，启动脚本、开发包名和服务标识均使用 GVPAK Studio。旧版的本机数据目录设置、浏览器草稿和 Windows 凭据会迁移到新命名下，已有图片与项目仍使用原数据目录。迁移模块仅为读取旧配置保留原存储标识，不会输出密钥或把凭据写入文件。
